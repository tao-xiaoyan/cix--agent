# 集成约定与待确认项

1. A/B 从相同架构提交开始，分别在平台目录实现服务与 Mock。
2. Mock 读取 shared/examples/events.json；连续生成时必须更新 UUID 和 UTC 时间，不能把示例固定 UUID 当新事件持续发送。
3. A 通过统一入口验证后写 SQLite/outbox，实时流使用 RealtimeMessage；B 按共享模型接收并验证每条事件。
4. 本地连调验证 accepted、duplicate、内容冲突、单项无效、断网重试、重启恢复、鉴权越权与分页时间边界。
5. 验证任务创建幂等、状态轮询、结果关联、端侧回写去重及无重复上传。
6. 用户准备真实模型后，仅替换 Adapter；先验证字段、窗口及质量映射，再做性能和 ARM64 验证，不改变事件入口。

契约变更先提出：受影响字段/接口、原因、旧客户端兼容方式、版本策略、迁移与回归测试。必须由架构任务修改 shared/ 后重新导出 JSON Schema/OpenAPI。A/B 不通过增加私有字段绕过额外字段校验。

尚需用户确认：

- 串口帧格式、编码、校验、时间来源、通道名称、单位、采样率、缺包和断线判定。
- 生理窗口长度/步长、模型实际输入输出、分类标签、置信度含义和适配器生命周期。
- 睡姿及音频类别，姿态关键点规范、追踪 ID 规则、图像/音频预览传输需求。
- 异常定义、确定性阈值、告警策略、允许执行的工具及人工确认边界。
- 设备数量、事件吞吐、网络带宽、离线时长、SQLite 容量及已确认数据留存策略。
- 云服务器资源、域名/TLS、备份、鉴权注册和密钥轮换方式、操作者权限范围。
- 云端分析方法、任务保留时间、轮询间隔、是否需要未来入站回写。
- 原始视频/音频/生理数据是否存储、访问权限、脱敏与保留期限。

以上未知项不阻碍 Mock 开发，但在真实硬件与生产集成前必须确认。当前产物是工程协议基线，不对模型效果或健康结论作验证。
